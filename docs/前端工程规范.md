# 前端工程规范

规范的作用是让"下一次改动"不需要重新做决定。以下每一条都对应 ESLint 规则或目录约定,
不是倡议。

## 一、分层与依赖方向

```
types → lib → features → components → app
```

| 目录 | 可以有 | 不可以有 |
| --- | --- | --- |
| `types/` | 类型、常量、纯函数式工具 | 任何运行时依赖 |
| `lib/` | 纯逻辑与算法 | React、DOM、IO、全局状态 |
| `features/` | 业务编排 | 直接操作 DOM |
| `components/` | 视图 | 直接调用上游 API |
| `app/` | 组装、路由、API Routes | 业务逻辑(应下沉到 features/lib) |
| `server/` | 密钥、上游调用、文件系统 | 被浏览器代码引用 |

## 二、组件

1. **`components/ui/` 是纯展示组件**:只接受 props,不认识 store、不认识业务类型。
   它必须能在另一个项目里原样粘贴使用。
2. **一个组件一个文件**,文件名与组件名一致。导出的组件用命名导出,不用 default
   —— 重命名时不会被静默改坏。
3. **组件不写死颜色**:一律走 `globals.css` 的语义令牌(`text-ink-2`、`bg-surface` …)。
   硬编码 `#fff` 在白天模式下必然出问题。
4. **超过三层的 JSX 嵌套拆子组件**,而不是加注释分层。

## 三、状态

- 能放在组件里的状态不放 store;能由 props 推导的不放 state
- store 只装**跨组件共享**且**需要跨路由存活**的状态
- 高频变化的值(指针坐标、相机)走 `ref`,让渲染循环直接读 —— 走 state 会把整棵子树拖下水

## 四、动效

- 时长与曲线只用 `globals.css` 里的 `--dur-*` 与 `--ease-*`,不就地发明数值
- **动画按秒计算,不按帧计数**;`dt` 上限 64ms,防止切回标签页时跳变
- 尊重 `prefers-reduced-motion`
- 过渡只改 `transform` / `opacity`,避免触发布局

## 五、错误处理

- 上游响应用 schema 校验后再进业务层,不信任任何外部 JSON
- 大模型的输出一律当作**不可信输入**:校验失败就重试,超过次数则降级为"无结果",
  而不是把半截 JSON 渲染出去
- 面向用户的错误信息说清"发生了什么 + 可以怎么办",不暴露堆栈

## 六、提交

提交信息用 `<type>(<scope>): <中文描述>`:

```
feat(kg): 知识图谱模型与关系预设类型
fix(layout): 增量构建时老星体被整体平移
docs(design): 视觉编码表
perf(render): 星图绘制合并为单次路径
```

一次提交只做一件事。**重要改动必须提交** —— 赛题明确要求保留能体现真实开发过程的
Git 历史。

## 七、验证

```bash
pnpm check     # 类型 + 规范 + 设计令牌一致性
pnpm build     # 生产构建必须通过
```

改动渲染或布局后,除了命令通过,还要在浏览器里实际看一眼 —— 类型系统不知道
"星体挤成一团"长什么样。
