# 架构设计

## 一、一条贯穿全局的约束:依赖单向

```
types  →  lib  →  features  →  components  →  app
                                          ↗
                        server  →  app/api
```

- 左边的东西永远不知道右边的东西存在
- `lib/` 是纯逻辑:没有 React、没有 IO、没有全局状态
- `server/` 只被 `app/api/**` 引用,**绝不允许进入浏览器包**(密钥红线)
- `components/ui/` 不认识业务、状态与数据源,才能在别处复用

这条约束写进了 `eslint.config.mjs`,违反即构建失败。之所以用工具而不是靠文档,
是因为"这次先这样、下次再拆"从来不会真的拆。

## 二、为什么后端只做 AI 接入层

赛题原文要求"前端 Web 应用为主要呈现形态,后端服务仅作为 AI 能力的接入层"。
因此本项目的服务端只有三类代码:

1. **上游数据源适配**(`src/server/sources/`):把 OpenAlex 的字段翻译成我们自己的模型
2. **大模型调用**(`src/server/llm/`):提示词组装、结构化输出校验、重试与降级
3. **图算法**(`src/lib/graph/`):纯函数,可以脱离服务端跑,也方便单测

没有数据库、没有登录态服务、没有独立的业务后端。用户数据存在浏览器侧,
图谱产物存在文件系统缓存里(可按上游重建,因此不入库)。

## 三、数据流

```
用户输入种子论文
      │
      ▼
① POST /api/seed/resolve      解析候选(标题检索 / DOI / arXiv ID)
      │                        ★ 永远返回候选列表,由用户确认 —— 不替用户决定
      ▼
② POST /api/starfield/grow    展开引文邻域 → 建图 → 聚类 → 布局 → 关系判定
      │                        关键:老节点坐标是锚点,世界只对称长大
      ▼
③ GET  /api/starfield/:id     取回图谱载荷
      │
      ▼
④ POST /api/ask               检索增强问答(流式),每条引用带回 chunkId
```

每一步的产物都落盘缓存,缓存键带**格式版本号** —— 结构一改就换版本号,
避免旧格式被当新格式读出来。这条规则来自一次真实事故:界面上出现了一整片
`undefined` 的节点。

## 四、渲染架构:为什么是 Canvas 而不是 SVG/DOM

上千个节点、上千条边,如果每个都是 DOM 元素:

- 内存与样式重算的开销随节点数线性增长
- 布局一动,浏览器要做上千次样式计算
- 悬浮高亮需要改上千个元素的类名

Canvas 把这三种开销压成一次绘制调用。代价是**要自己实现命中检测**,
但那本来就是必须做的 —— 我们需要的命中检测带有空间语义(命中半径随缩放变化、
空白处要有吸附),DOM 的 `:hover` 帮不上忙。

### 三条性能约定

1. **布局在服务端算完**(ForceAtlas2 放到 API 层),前端只做投影 → 主线程不跑 O(n²)
2. **悬浮/选中双写**:渲染循环读 ref,React 读 state → 高频状态不触发重渲染
3. **动画按秒计算,不按帧计数**,`dt` 上限 64ms → 在 120Hz 屏与切标签页回来时都不失真

### 语义缩放

缩放不是把同一张图放大缩小,而是**切换抽象层级**:

| 缩放区间 | 看到什么 | 读的是哪一层 |
| --- | --- | --- |
| 拉远 | 领域星云 + 中文标题 | `domain` |
| 中间 | 星团 + 社区标签 | `community` |
| 推近 | 论文星体 + 关系边 | `paper` |

阈值集中在 `src/types/starfield.ts` 的 `VIEW_LEVEL_THRESHOLDS`,不散落在组件里。
过渡用同一条缓动曲线做时间平滑:无论用户缩放多快,浮现与隐没都走同一条曲线。

## 五、AI 管道

### 关系判定的两段式设计

```
候选生成(确定性)
  引用邻域 + 向量近邻 + 概念共现
        │
        ▼
硬约束过滤(确定性,不花 token)
  年份差 / 互引检查 / 共享任务 / 相似度下限
        │  候选量级从 O(n²) 降到 O(n·k)
        ▼
模型判定(带 rubric 与反例)
  输出结构化 JSON,并要求给出原文证据片段
        │
        ▼
校验与入库
  不变式检查(语义边必须有证据)→ 违反即丢弃并记录
```

**为什么要给反例**:只给正例是幻觉的主要来源。模型不知道边界在哪,
就会把所有"看起来差不多"的论文对判成同一种关系。

### 反幻觉的三道闸

1. 结构层的事实只能来自上游 API,模型无权修改
2. 语义层的每条边必须有原文片段作为证据,界面上可以直接展开阅读
3. 派生层的结论必须可复算 —— 统计检验结果连同参数一起呈现

界面上,这三种信息的视觉表达刻意不同:模型说的用虚线,数据源说的用实线。

## 六、渲染与数据的分离

`src/components/star-map/render.ts` 是一个**纯函数**:输入场景描述,输出绘制结果,
不接触 React、不接触 DOM。好处:

- 可以脱离浏览器跑,便于做像素级回归
- 可以在 Node 里生成截图用于文档
- 渲染逻辑的改动不会牵动组件生命周期

## 七、缓存与成本

| 层级 | 存什么 | 失效条件 |
| --- | --- | --- |
| 邻域缓存 | 一篇种子的引文邻域原始响应 | 格式版本号变更 |
| 嵌入缓存 | 论文文本块的向量 | 模型变更 |
| 图谱载荷 | 整张星空 | 格式版本号变更 |

演示时的关键路径(第二篇种子起)几乎不发请求,因此可以离线展示。
