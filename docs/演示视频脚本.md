## 一、演示顺序

1. **先问题，再作品**：前 30 秒讲清“看得见引用，看不见为什么相关”。
2. **先建图，再问答**：星图是舞台，RAG 是演员。
3. **先证据，再 Agent**：每条关系能回到原文，再展示“不足就补查、够了就停”。
4. **补齐三项能力**：多模态、摘要翻译、模型服务与按功能选模型。
5. **先单机，再生态**：MCP 证明作品能被外部 Agent 复用。
6. **先能力，再工程**：账号隔离、密钥加密、限流预算、15 项检查。
7. **先当下，再长期**：并入新种子，旧星不动、新星生长。

### 镜头 01｜片头：问题

**时间** 00:00.0–00:10.3（10s）  
**画面** 黑场题卡 → 首页星空淡入。片名、赛道、团队。  
**解说词**

> 读一篇论文，我们常常看得到它引用了谁，却看不出，这些工作之间到底是什么关系。

**包装** 片名卡；右下角赛道信息。

### 镜头 02｜首页：把文献调研变成星空

**时间** 00:10.3–00:29.4（19s）  
**画面** 首页全景，缓慢推近标题与输入框；关键词“论文是星，关系是引力线”。  
**解说词**

> 对研究生和跨领域研究者来说，传统文献工具给你列表和引用数。StellarLit是一个关系型文献图谱，它想把文献调研变成一片可以走进去的星空：论文是星，关系是引力线。

**包装** 左下角小字：看得见引用，也要看得见为什么相关。

### 镜头 03｜团队：单独一页

**时间** 00:29.4–00:53.6（24s）  
**画面** 整页团队卡：队名、队员、指导教师、赛事信息、三个关键词、五项 AI 亮点。  
**解说词**

> 我们是西安交通大学白白BAB队，参加2026传智杯AI WEB网页开发挑战赛，赛道10037。三个关键词：可质疑的关系图、会长大的星空、能对话的图谱；背后是关系判定、Agent、混合RAG、多模态和MCP。

**包装** 整页排版，不再用浮窗；底部一行品牌语。

### 镜头 04｜建图：从解析到展开

**时间** 00:53.6–01:14.1（20s）  
**画面** 输入种子 → 右侧构建面板逐项打勾（解析种子 / 核对目标 / 展开引文邻域）→ 五步流水线整页卡。  
**解说词**

> 输入标题、arXiv ID或DOI。系统先解析种子，核对目标，再展开引文邻域；结构骨架先落下来，语义关系再一条条亮起。候选不够明确时，它会把选择交给你，不替用户猜论文。

**包装** 五步：解析种子 / 核对目标 / 展开引文邻域 / 关系判定 / 布局投影；注明 40+ 次上游请求、按种子缓存、增量并入。

### 镜头 05｜缩放：领域星云与论文星体

**时间** 01:14.1–01:35.1（21s）  
**画面** 星图全景 → 滚轮拉远到领域层，出现“计算机科学”标签并加标注 → 推近回论文星体。  
**解说词**

> 滚轮拉远，论文星体收成领域标签——计算机科学；推近，又回到每一篇论文。同一张图，在不同抽象层级之间切换。老节点的坐标是锚点，后面并入新种子时，星空只在原地长大。

**包装** 领域标签旁加“计算机科学 · FIELD 领域星云”标注线。

### 镜头 06｜多点星：视角移动与关系证据

**时间** 01:35.1–02:08.4（33s）  
**画面** 连续点三颗星，镜头随之移动、重新聚焦 → 展开关系与原文证据。  
**解说词**

> 点开任意一颗星，右侧不是泛泛的摘要，而是它和其他论文的关系；再点旁边一颗，视角会跟着移动、重新聚焦。六类语义关系：基线、扩展、同期、思路类似、同任务异方法、结论矛盾。每条语义边都必须带证据：原文片段、引用记录，或可复算的相似度，并标明是模型判定还是数据源事实，置信度多少。

**包装** 右下角图例保留六类关系；证据卡标注判定来源与置信度。

### 镜头 07｜关系设置：标准可调

**时间** 02:08.4–02:32.0（24s）  
**画面** 设置 → 关系判定：六类关系、硬约束、置信度阈值、自定义标签。  
**解说词**

> 关系标准也不是写死的。在设置里，你可以调整引用条件、年份差、文本相似度和证据标准；还可以新建自己的关系标签，让同一对论文携带多个语义。改完之后，只影响新建或并入的星空，不会偷偷改历史结论。

**包装** 右上角：6/6 启用 · 关系预设上限 24 条。

### 镜头 08｜RAG 问答：回答要有出处

**时间** 02:32.0–03:16.4（44s）  
**画面** 文献问答：流式回答、角标回原文、检索状态、证据卡。  
**解说词**

> 接下来问一个真正的研究问题：这几篇论文的研究脉络是什么？回答是流式生成的，但不是让大模型自由发挥。系统先拆解问题，用BM25做词面召回，再经图结构扩展和证据阈值筛选；绑定向量模型后，还会与向量召回做RRF融合。回答里的每个角标，都能点回原文。你看这一段，它引用的是关系证据，不是模型编出来的结论。这样一来，回答从“模型说的”，变成“有出处的”。而且它知道，什么时候该停下来。

**包装** 右上角检索状态；回答内角标可点击。

### 镜头 09｜Agent：不足就补查，够了就停

**时间** 03:16.4–03:40.9（24s）  
**画面** 决策轨迹：规划 → 工具 → 证据不足 → 补充检索 → 停止。  
**解说词**

> 展开决策轨迹：它先规划，再调用工具；判定证据不足，就补查一轮；证据够了，立即停止。最多两轮、五步。每一次判断都留在界面上。停止条件不是模型拍脑袋，而是可解释、可复现的证据覆盖规则。

**包装** 右上角：Agent 上限 2 轮 / 5 步。

### 镜头 10｜多模态：让图表也能被追问

**时间** 03:40.9–04:16.9（36s）  
**画面** 上传图表提问 → 图像证据卡 → 原图区域高亮。  
**解说词**

> 除了文字，它也能读图。最多上传四张图片，视觉模型会抽取OCR、表格、图表序列和关键数值，并把结论归一化到原图上的区域坐标。点开图像证据，右侧会高亮它引用的那块区域。读论文里的实验图、对比表，不用再在PDF和聊天窗口之间来回找。每张图不超过4MB，支持JPG、PNG、WebP和GIF。

**包装** 证据卡：图像证据 · 图表 · 数值；底部：最多 4 张 · 单张 ≤ 4MB。

### 镜头 11｜摘要翻译：英文摘要一键读懂

**时间** 04:16.9–04:33.6（17s）  
**画面** 论文详情 → 点“翻译” → 中文摘要 → 显示原文切换。  
**解说词**

> 英文摘要读起来费劲，点一下翻译。它只翻译、不总结，保留术语和方法名；需要核对时，一键切回原文。翻译和问答，可以绑定不同的模型。

**包装** 摘要下方“翻译 / 显示原文”切换。

### 镜头 12｜MCP：把星空交给外部 Agent

**时间** 04:33.6–05:08.7（35s）  
**画面** 设置页 9 个只读工具 → 个人令牌 → 独立 MCP 客户端调用与 chunkId。  
**解说词**

> 这片星空不只在网页里。我们把图谱和检索封装成9个只读MCP工具：列出星空、读结构、检索原文、查关系证据、展开引文邻域……外部Agent拿到个人令牌，就能通过HTTP或stdio接入。这里用一个独立的MCP客户端问同样的问题：它会自己调用工具，拿回带chunkId的证据。所有工具只读，不会改动已保存的星空。

**包装** 左上角 MCP Server 名；右上角 readOnlyHint · 个人令牌。

### 镜头 13｜模型服务：按功能选模型

**时间** 05:08.7–05:33.7（25s）  
**画面** 模型服务：十家服务商卡片 → 添加服务商弹窗 → 四个功能分别绑定模型的下拉。  
**解说词**

> 模型不是绑死在一家。设置里可以接入OpenAI、Claude、DeepSeek、通义、Kimi等十种服务商。每个功能单独选模型：关系判定用快速模型，多模态问答用视觉模型，摘要翻译用更强的模型，向量检索单独绑定嵌入模型。

**包装** 服务商：OpenAI / Claude / DeepSeek / 通义 / Kimi / MiniMax / 混元 / MiMo / NVIDIA / 自建兼容接口。

### 镜头 14｜工程与安全：能演示，也能上线

**时间** 05:33.7–06:09.6（36s）  
**画面** 账号用量 → 模型服务绑定 → pnpm check 15 项全绿。  
**解说词**

> 工程上，前端是Next.js15、React19、TypeScriptstrict；星图用Canvas渲染，布局在服务端算完，前端只做投影。安全边界做在链路里：APIKey用AES-256-GCM加密、按账号隔离；IP限流、并发上限、每日token预算；资料与指令隔离，防提示词注入；模型失败时结构化降级。仓库有15项检查。

**包装** 左侧标签：加密 · 隔离 · 限流 · 预算 · 兜底。

### 镜头 15｜并入：旧星不动，新星生长

**时间** 06:09.6–06:30.7（21s）  
**画面** 历史星空 → 打开 12 篇的星空 → 顶部输入 BERT → “并入”按钮 → 12→240 增量角标。  
**解说词**

> 星空不是一次性的。顶部输入框换一篇种子，点并入；旧星坐标不动，新论文沿着引用和语义关系长进来。这片星空从十二篇、三十二条边，长到二百四十篇、两千二百一十六条边。

**包装** 右侧角标：12 → 240 篇、32 → 2216 条边；旧星坐标不变。

### 镜头 16｜收尾：从读列表，到看星空

**时间** 06:30.7–06:47.5（17s）  
**画面** 星图缓慢拉远 → 片尾题卡。  
**解说词**

> 我们相信，开放科学不只是让论文免费，更是让每个人都能看见知识之间的关系。StellarLit，把文献调研从读列表，变成看星空。谢谢观看。

**包装** 片尾：团队、赛道、仓库/演示地址。
